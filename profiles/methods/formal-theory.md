# 形式与理论：证明纵向切片

画像 ID：`formal-theory`；版本：`0.1`；当前重点变体：`proof`。这是宿主代理执行证明工作的指导，不是证明器或正确性认证。分析推导可借用相关原则，但其全部物理或数值义务尚未覆盖。登记方式见 [接入协议](../../core/skill-bridge.md)。

## 确定命题

先写出对象、定义域、量词、假设与结论；区分候选问题、已知引理、本文拟建立结果和计算观察。检查稿件有没有将“几乎处处”改成“处处”、局部结果改成全局、存在性改成唯一性，或混用不同范数、收敛方式与概率陈述。

检查最小情形、边界与退化情形能迅速暴露缺失假设。若找到反例，先说明它符合哪些假设、违反哪条结论，再判断是否有值得证明的修正版；不继续为原错误结论补造证明。有限枚举或数值观察不能覆盖未枚举的无限对象。

## 展开证明义务

把关键推断展开到读者可以逐步核查的程度。标明依赖引理及其实际条件；引用材料需给出可定位处，不能只以题录代替引理支持。若使用材料外的标准事实，明确陈述并给出所需范围内的论证，或保留为待核对依赖。

涉及极限、积分、求和、微分、条件期望或算子交换时，检查具体对象是否满足相应条件。局部检查应围绕真实推断，避免机械列出与问题无关的分析定理。

证明可以有多个有效路线，不要求套用统一结构。存在缺口时指出卡在哪一步、缺什么条件或引理，以及哪些结论仍成立；部分推导不写成完整证明。

## 工具与交付

符号计算、有限检查与形式化工具可以支持特定义务。报告实际命令、输入、范围及工具结果；没有运行证明器时，不把手工证明或登记检查描述为已形式化验证。

交付可独立理解的命题与证明，或明确反例和修正版。写清已建立的范围与尚未处理的延伸。持续项目将证明／反例文件作为 evidence 或 artifact，与相应 statement 的 supports、qualifies 或 challenges 关系分开登记；具体字段见共用接入协议。

该切片检验证明行为，不依据问题包装、代理数量或完成活动自动判断原创性。文献定位另由 `rw-literature` 处理。
