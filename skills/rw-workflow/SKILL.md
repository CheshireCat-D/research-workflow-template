# 科研流程

按当前研究对象、已有材料与用户交付目标组织工作。先读 [接入协议](../../core/skill-bridge.md)；持久记录与恢复状态遵守 [核心协议](../../core/protocol.md)。

## 选择当前入口

已有项目先读取配置、登记与恢复摘要，确认哪些工作实际完成、哪些输入已变化。聊天中的旧计划只作线索；不要将其补写成已执行活动。存在过期活动时，定位变化及受影响范围，再决定复核或调整下一步。

从研究兴趣启动时，先明确一个可推进的问题及资源边界。已有稿件、数据或证明可直接从其缺口进入；不要求重做选题，也不要求每项研究走相同顺序。

按本次缺口加载相邻技能，不一次加载全包：

| 当前工作 | 技能与任务 |
|---|---|
| 兴趣、研究问题或取舍未定 | `rw-question`：形成有范围的问题，确定下一项能改变决策的检查 |
| 需要已有依据或来源定位 | `rw-literature`：查来源身份、访问范围及原文支持 |
| 已有问题卡在机制、构造或解释瓶颈 | `rw-innovation`：发展具体提议，列出成立义务和最小反驳检查 |
| 多个实际候选需要对抗比较和取舍 | `rw-candidates`：比较最强论据、有效反驳、未知及关键下一项检查 |
| 需要证明、计算或材料解释检查 | `rw-validation`：按适用方法开展有边界的验证 |
| 需要起草、润色、翻译或压缩 | `rw-writing`：按作者目标交付文本 |
| 需要科研数据图、可编辑示意图或图件审查 | `rw-figures`：保留科学含义与来源，交付可编辑源和实际核验的图件 |
| 需要审阅、返修或交付核对 | `rw-review`：报告证据支持的缺口并处理获授权的修改 |

这些技能与本技能同在 `skills/` 的相邻目录，项目内接入后也保持相邻。按本轮任务加载所需入口；有已定路线时不强制创新或重新比较候选。

## 研究代码与工具维护

仅在实现或维护研究代码、实验脚本和工具时，先读相关调用者、接口约定及现有风格。复用足够的已有结构；新增抽象、依赖或配置层应解决当前明确需求。改动围绕目标行为，不夹带无关重构或格式化；清理由本轮修改造成的无用代码或依赖，其他发现按本次授权处理。

按变更风险选择与受影响行为有关的验证；缺陷修复先尝试复现具体失败，简单修改不机械新增测试。保留必要的输入检查、错误处理和兼容性约束，科学结果继续遵守相应方法的验证要求。关键歧义、停止条件和交付沿用本流程；本小节不限制获授权的理论构造、研究探索或文字重组。

## 推进与交接

研究活动按真实依赖连接。只对当前任务需要的记录写入来源、主张、证据、活动或产物；不要为了填满工作流而制造记录。学科名称用于语境，方法用于证据要求，跨学科项目可以组合方法。

需要学科语境时，按项目所选学科读取 [学科画像目录](../../profiles/disciplines/) 中对应的文件；尚未选定时不全量加载。画像帮助辨认研究对象与常见外推风险，具体工作仍按方法开展。跨学科部分分别保留证据对象和适用范围，再说明如何连接结论；真实材料或行动的权限按 [治理说明](../../profiles/governance.md) 处理。

完成一项工作时，在工作记录与交接中说明产物、对应主张和实际依据，只列影响结论或下一步决策的尚存问题；稿件正文按 `rw-writing` 的“正文与工作记录”边界表达。将失败、反例、无结论或需要修改的问题保留下来；它们可以改变研究方向。

持续项目在适当节点保存有具体下一步的检查点。下一步应说明作用于哪个对象、要解决哪个不确定性，而非“继续优化”。检查点用于恢复上下文，不是完成证明、实验或审阅的替代。

面向用户优先交付本轮结果与下一步。只有资源、材料或关键选择尚缺且会改变行动时才提问；明确授权的局部工作继续推进。
