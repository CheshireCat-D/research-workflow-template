# 研究问题与选题

先读 [接入协议](../../core/skill-bridge.md)。需要持续登记时遵守 [核心协议](../../core/protocol.md)，以问题类型的 statement 保存尚未作出结论的提问。

## 找出影响选择的信息

从用户已有兴趣、材料与约束中识别研究对象、想解释或建立的关系、已有基础和可用时间。只询问会改变选题或首项工作的关键缺失；已有答案不用重复询问。用户给出明确问题时，直接检验其范围与可行性。

把宽泛主题改写成能被处理的问题，给出对象、条件、所求结论或解释范围。数学问题明确量词和假设；计算问题明确任务、比较对象与评价量；解释性问题明确材料集合、时间语境与竞争解释。不要把所有问题都改写成统计假设。

专业小类尚未对应到入口时，按需读 [专业与问题导航](../../profiles/selection.md)，用研究对象和证据选择已有学科与方法。导航示例不代表该专业已专项验证，也不要求为每个专业创建独立技能。

法学问题先辨明法律解释、比较研究、规范建议或效果研究；确定会改变下一步的法域、相关事实日期与分析时点，按需读 [法学语境](../../profiles/disciplines/law.md)。已经给定的边界直接使用，未知的关键事实保留条件分析，不为填表重复追问。

区别问题本身值得研究、现有材料能回答、预期有新贡献这三个判断。缺少文献依据时，将新颖性保留为待查；把已有教材性质问题称为练习或复核，不凭包装升格为发现。

## 候选与最小下一步

只有实际存在多个待选问题时才比较。采用能改变取舍的依据，例如已有结果重叠、关键材料可获得性、证明或实验瓶颈，以及失败后仍可得到什么。说明依据和未知，避免凭空给精确分数。用户已选定路线时，保留其选择并检查下一步所需条件。

初步问题卡需要正式对抗比较时使用 `rw-candidates`；问题已清楚但缺少具体机制或构造时使用 `rw-innovation`。一次轻量澄清不必启动多角色评审，也不必额外生成技术新方案。

为目前最有价值的问题提出一项小而有辨别力的检查：它应能排除一种解释、暴露一个假设、发现反例、检验数据可用性，或判断预期方法是否有用。说明不同结果将怎样改变后续行动。具体执行交给 `rw-literature` 或 `rw-validation` 的适用分支。

交付一张简短问题卡或等价文字：当前问题、范围、已有依据、最大不确定性、下一项检查。若作了取舍，保存理由及重新考虑的条件。不要为单次选题讨论强制建立完整项目或论文框架。
