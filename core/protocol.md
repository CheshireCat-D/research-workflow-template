# 核心协议

核心只管理研究记录、文件身份和恢复状态。`check`、`status`、`resume` 为只读命令；不执行记录中的命令、不检索或上传材料、不判断科学真伪。

## 权威与版本

- `project.json` 保存项目配置；`records/registry.json` 保存唯一权威登记、记录版本、修改历史、恢复游标和最近检查点。
- `PROJECT.md` 保存作者笔记，不反向覆盖 JSON；不会要求同时手工同步多份台账。
- `schema_version=0.1`。结构契约来自 `model.py` 的定义；`schemas/` 为同源生成的 JSON Schema。内置校验器只支持这些定义实际使用的关键字，不是通用 JSON Schema 引擎。
- 每条记录首次登记版本为 1。替换必须显式提供 `--replace --expected-version N`；旧版本进入修改历史。注册不会自动新增支持评估。

## 证据与活动

本地证据和产物使用项目相对路径，登记时记录 SHA-256；拒绝内部符号链接、父路径和非普通文件。本地单文件指纹上限 256 MiB，元数据 JSON 上限 8 MiB；超限明确报错，不能用截断摘要冒充完整指纹。

项目配置、登记簿本身和 `.research/` 内部状态不能登记为本项目的本地研究证据或产物，以避免自引用；同一文件的硬链接或文件系统大小写别名同样受保护。内部状态身份检查最多遍历4096项，超限明确报错。作者笔记等实际材料仍可显式登记。

外部或受控证据只登记定位及访问说明，不抓取、不读取原件，也不认证访问许可。来源身份、证据及其与主张的关系独立记录；支持和挑战可以并存，不按数量自动裁决。核心只校验方法绑定的 ID、变体和对象引用；具体方法指导由宿主按技能与画像执行，CLI不执行研究方法。方法的评估证据位于完整发行包，不随项目内运行资源复制；`options` 的 `task_evidence` 明示其基址与可用性，本地画像仍相对工具包根解析。

标记活动 `done` 时保存所声明输入、输出和传递依赖的记录版本及本地文件指纹。后续变化会使活动的派生 `effective_status` 为 `stale`，而不改写作者原始状态。`failed`、`skipped` 需要原因；它们不被视为完成。活动完成只表示作者登记该工作已做，不构成证明、伦理批准或投稿认证。

记录实际执行者与工具：代理开展的解释、编码或推导不能标成人类研究者已执行或已作独立人类验证；程序核对也不能代替未做的内容审阅。原材料中的人物与叙述身份和本次实际分析者分别说明。

检查点保存配置、当前记录及本地资源的摘要，并保存下一步。读取恢复状态不会重新绑定变化的证据；即使显式保存新检查点，旧完成活动的失效仍需逐项复核后显式更新。恢复命令只提供建议，不执行下一步。

## 写入与平台范围

初始化拒绝已存在的目录、文件或断链；macOS/Linux 写入使用项目内 POSIX 文件锁与目录文件描述符，Windows 使用原生目录／文件句柄及非阻塞文件范围锁；元数据使用同目录临时文件和单文件原子替换。锁随进程退出由操作系统释放，锁文件存在不意味着仍被占用。元数据写入不更新作者笔记或研究材料。

核心面向 Python 3.11+ 的 Windows、macOS 和 Linux，使用标准库。Windows 内部路径拒绝重解析点（包括 junction 和符号链接）、设备名与歧义路径；访问期间保持相关目录句柄。当前真正运行过的平台与解释器由核验记录说明；没有执行的环境不得记为通过。网络文件系统、极端掉电恢复、恶意并发修改整个目录及全部学科方法的正确性不在完整验证范围。
