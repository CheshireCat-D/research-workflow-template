# 问题与预定方法

对象为输入需求 v1 的 WindowGate，部署范围仅单进程、单线程、内存。五个冻结输入已逐个复制并记录 SHA-256；只读取本案例原始材料及工具包指导。无外部文献、私人数据、网络、部署或安装活动。

采用 engineering-design/software-prototype 与 computational/empirical-algorithm，均读取项目内版本 0.1；工程画像要求需求—设计—运行对应，计算画像要求独立基准、实际失败和可复跑产物。学科 engineering v0.1 提供原型与部署分层语境。已加载 rw-workflow、rw-validation、rw-writing、rw-review。

## 先固定验收

|需求|判据与独立检查|
|---|---|
|R1 配额与重复时间|手工预期序列；同一时刻容量用满后拒绝|
|R2 区间左端开、右端闭|恰好 t-window、相邻浮点、跨空窗|
|R3 拒绝不占用额度|拒绝后在最早请求到期时仍可获准|
|R4 客户隔离|跨客户时间逆序；各自重复时间容量|
|R5 构造校验|limit/window 非法类型、bool、零、负值、非有限值必须 ValueError；大整数为合法有限数|
|R6 请求校验|client 与 timestamp 逐类非法值须 ValueError|
|R7 单客户水位|合法时间下降必须 ValueError；拒绝也推进水位|
|R8 异常原子性|深拷贝状态前后相等；非法新客户不建状态；随后合法请求可正常运行|
|R9 数值保真|超出 binary64 整数精度与 float 范围的合法整数；分数窗口|

先写 artifacts/run.py 并对 inputs/gate.py 运行；其固定手工用例与 1512 个确定性单客户参考轨迹用于修复后复跑，不因基线失败调整判据。参考器保留全部已允许历史，每次直接用定义计数，不采用待测的队列删除算法。参考轨迹为时间 0..4 的非降五元组、limit=1,2,3、window=1,2,3,2.5。另独立重放演示 CSV。无随机性，种子不适用。

## 方案与取舍

保留每客户 deque 与独立合法请求水位，适合指定内存接口；直接扫描全部历史更易作参考但内存无限累积，故只用作小规模独立核对。时间数字精度若需修复，优先精确表示所给 int/float 数值，避免未授权舍入；不另设大小阈值。没有执行生产负载、安全、持久化或并发检查。
