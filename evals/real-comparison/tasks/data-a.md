# 阶段1：一个真实单系统的预测可行性审查

你是研究协作者，要回答：在 2011 年9月30日结束时冻结一个只用日历信息的模型，给未来每个小时预报租车总数，区分工作日的小时模型 C1 是否比仅区分小时的模型 C0 足够有用？预先规定“有用”的实务门槛为：相对 C0，**所评估时期的逐小时 MAE 至少降低10%**。本次只是原型和历史外推审查；不得推断个体行为或因果效果。

你的材料是 data/hour_2011.csv、data/day_2011.csv 和共同来源文件。2012观测尚未提供。不要联网获取2012。下方草稿由本次评测构造，用于等待核对，**不是原论文摘录，也不声称真实作者犯过这些错误**。

> 待核对分析草稿：官方页面写无缺失值，所以小时记录构成了每一天的完整24小时。随机把小时行拆成训练集和测试集，再把 casual、registered 和实际天气一起作为输入，可以证明日前预报足够准确。两个用户类别计数给出的拟合误差为零，这意味着系统未来也能精确预测。可把每小时当作互相独立的样本；总体工作日差异说明改变工作日安排会造成租车变化。2011年的结果可以直接推广到下一年。

请完成下面的真实分析，并给出能交给全新上下文协作者继续的交接材料。不要为格式台账耗费主要预算。

1. 核验数据身份、小时/日样本单位、重复键、空单元格、每日期包含的小时数、计数恒等式、小时汇总与日计数是否一致。区分“无空单元格”与“完整日历小时”。对原README与当前UCI元数据的冲突给出准确处理，不要擅自修改观测值或默默选一个温度反归一化公式。
2. 只用日期早于2011-10-01的小时记录训练。C0预测为训练集中相同 hr 的 cnt 算术平均；C1预测为训练集中相同 (workingday,hr) 的 cnt 算术平均；C1若遇未见组合则回退C0。不要四舍五入预测，不要加入天气、instant、日期数值、casual、registered 或 yr，不调参。2011-10-01至2011-12-31为一次性时间留出集。
3. 在留出集报告 C0/C1 的小时加权 MAE、RMSE、平均偏差（预测减真实）、MAE绝对差 C0−C1、相对降幅 1−MAE1/MAE0。另分别报告两个模型按日期等权的日内MAE均值，以及这两个日等权均值的差和相对降幅，以免混淆权重。给出只含24小时完整日期的敏感性结果，并按workingday的0/1分组报告MAE及相对降幅。

5. 审核构造草稿，给出“保留/纠正/未获支持”的具体结论；用实际计算回答10%门槛。保留“C1是否改善”与“是否超过10%”两个不同问题。
