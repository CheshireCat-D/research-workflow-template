# 核心流程精简验收

本轮只改 RWT，九个技能入口保持原名。日常流程为“一次恢复 → 实际研究与复核 → 一次登记并保存”。项目命令默认使用当前目录；不向上查找、不自动初始化。修改已有记录时，`show --edit` 一次导出带固定版本的批次；登记加 `--next-action` 后在同一写锁内完成登记、检查点及恢复检查，再一次提交。只有断点文字变化时使用 `checkpoint --report`。

## 实际操作数

两份冻结用户包使用相同的真实公开企鹅 CSV、相同计算代码和相同登记，均从干净解压开始。旧流程已使用批量登记，没有故意追加 `check`。完整结果见 [summary.json](summary.json)。

| 同一目标 | 原流程 CLI 次数 | 精简后 CLI 次数 |
|---|---:|---:|
| 初次登记、检查点及恢复摘要 | 3 | 1 |
| 输入改变后导出两条记录、更新并查看恢复摘要 | 5 | 2 |
| 移动整个项目后在新进程恢复 | 1 | 1 |
| 单独保存检查点并查看恢复摘要 | 2 | 1 |

共同初始化、数据分析、子集生成和客户端 JSON 编辑单列，不计入上表；命令减少不等同于总用时或工作量按比例减少。初始 344 行、完整观测 333 行；删除首个完整观测得到 343 行的敏感性子集，实际重新计算后更新活动。两臂数值摘要、文件指纹、有效活动状态及检查点状态一致。9 次只读检查均保持文件字节、mtime 及目录元数据不变。

## 保留的检查

新检查点不能刷新旧活动绑定：输入改变后仍报告 `file_changed` 和 `activity_stale`，保存成功而检查有发现时返回退出 1；先查看 `registered` / `checkpoint_saved`，不能盲目重试。导出的固定版本遇到另一个客户端更新时，返回 `version_conflict`，失败调用不改登记。

首次前向运行把多条引用写成重复的 `--edit` 参数，早期候选只保留末组；保存检查如实报出未更新输入，没有误报成功。现已同时支持单个参数后列多条引用与重复参数两种形式；重复同一引用仍拒绝。原失败、按原文档语法成功及最终包成功分别保留，见 [三轮记录](attempt-history.json)。

## 复跑与证据身份

[离线脚本](run_forward.py) 只使用 Python 标准库，输入数据须匹配摘要记录的固定 SHA-256。提供相应新旧用户包和本地 CSV，输出目录须尚不存在：

```sh
python3 -B evals/current/core-streamline/run_forward.py --old-archive OLD.zip --new-archive NEW.zip --input penguins.csv --output NEW_DIRECTORY
```

两份用户包及 CSV 不重复捆入源码。最终旧包 SHA-256 为 `1bf658b7895711bf786b3cf415a3c47dc2b214a31bace1d82e5b22ef00849ff2`，新包为 `d410a4d0a18b41ab49527da58da041416af7150cdf94c4180f93e8008c1390e1`。原始命令、stdout/stderr、退出码和项目快照在本地保留，公共摘要保留其指纹。源数据出处、版权与精确版本见 `summary.json.source`；本轮使用已缓存且指纹匹配的数据，没有重新联网获取。

本轮是确定性软件旅程，未测量人类首次使用效率、科研准确率或不同技能包排名。此前核心对照实验仍绑定其原包，未改写为本轮新接口的验收。当前完整回归及分发核验入口见 [最新记录](../latest.json)。
