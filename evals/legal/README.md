# 法学适配：任务、材料与验证范围

本目录为新增的 `law` 学科入口与 `legal-analysis` 方法保存两项离线任务。材料均为原创、明确标记的虚构法域、规范与裁判，不含真实案件或私人资料，不是可以援用于现实法律问题的法源。

## 两项任务

- `authority-time`：在有限规范材料中处理公布、施行、相关事实、过渡安排及不同事项的适用范围，比较不同文书的权限和依据，保留未取得正文的限制。
- `comparative-precedent`：在各自法院和法域规则下分析裁判正文、编辑摘要、关键事实及后续处理；先分别核对，再给出有边界的比较。

`cases/` 在执行前冻结。各 `input-manifest.json` 对六份实际输入记录 SHA-256，自身不自引用；执行记录另对全部七个输入文件记录指纹。执行者获得原始任务和当前技能／画像，使用独立临时项目，实际登记、保存检查点并运行只读恢复；没有提供评分标准或参考答案。`recordings/` 仅保存可公开的实际产物、规范化最终状态和执行摘要；原项目与含本地路径的完整日志保留在发布包外。

具体执行状态见 [coverage.json](coverage.json)，独立内容审阅见 [independent-review.json](independent-review.json)。审阅者与任务执行者分开，结论绑定输入、输出及实际读取资源；发现问题须先保留缺陷与修订记录，再重新核对，不能由实现者预填为通过。

## 自动回归检验什么

[法学专项测试](../../tests/test_legal_research.py) 用当前复制运行时重建记录，并检查：

- `options` 与初始化可发现法学、法律方法及其变体，搬迁后画像与模板仍可使用。
- 法学扩展元数据原样往返；无效方法／变体不改变项目状态。
- 全目录方法和场景被旧素材组与新增法学组完整分担，不靠跳过新增项通过检查。
- 输入、发布产物与已读画像的身份和独立审阅一致。
- `check/status/resume` 保持只读；实际依赖材料或已登记画像变化后，旧评估保持原样而相关工作标为待复核。

这些程序检查不重新调用模型，也不重新产生一次法律内容审阅；字节一致和登记成功不认证法律解释正确。两个任务不能代表所有法域、部门法、真实数据库时效或专业法律意见。[方法画像](../../profiles/methods/legal-analysis.md)和[官方来源记录](../../profiles/sources.json)另说明实际适用和访问范围。

旧 `evals/d2`、`evals/d3` 的输入、产物与独立审阅记录保持原样。原16个架构场景仍由旧材料核验，新增 `L01/L02` 在本组记录，不把旧任务结论扩充成新方法已被验证。
