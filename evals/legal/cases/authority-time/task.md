# 合成任务：申请跨越修法时点时，资料提交条件与后续数据处理如何分开研究

本案所有国家、机关、法规、案件、日期与材料均为本模板原创的虚构材料，不是真实法律，也不提供现实个案意见。只能依照本地输入形成有限研究结论；不要联网补出虚构来源。

请审查 `draft.md`，就 `facts.md` 中的开放档案阅览申请写一份不超过 1200 汉字的研究短稿。先明确法域、机关、申请事实和所研究的行为时点，再处理资料中的公布、施行、修订及过渡规定。区分申请的实体条件、机关后续处理身份资料的行为，以及研究检索截至日期。

比较中央制定法、地方实施细则、平台通知和数据库编者标记各自能支持什么判断。对发生冲突的材料说明依凭的规则、待核来源和可有条件成立的结论，不能把文件日期或材料条数当作自动裁断。逐项给出文件 ID、条/款或段落定位、实际读取范围；缺页、未取得正文和版本空缺要保留。

在系统临时目录中新建独立项目 `PROJECT`，不得修改本案例输入、工具包、其他项目或个人技能。先读当前 `skills/rw-workflow/SKILL.md`，再按任务选择所需子技能及法学画像和模板，按实际选择绑定 `law` 与 `legal-analysis` 的方法变体。

输入复制到 `PROJECT/inputs/`。交付 `notes/issue.md`（研究范围与方法）、`notes/authority-table.md`（来源和效力定位）、`notes/time-matrix.md`（时点和争议对照）、`manuscript/report.md`（可独立阅读的修订稿）和 `review.md`（依据、失败、待核与下一步）。不要求数值实验。引用须能从短稿返回实际获得的原文位置；不能把平台说明或编者标签写成裁判或制定法正文。

用当前 CLI 实际初始化、连接项目技能，并按交付内容登记 source、statement、evidence、relation、activity、artifact、method-binding。采用实际读取的画像版本，使用项目相对路径。保存 checkpoint，实际运行 `check`、`status` 与 `resume`，保存命令和退出码；登记一致性不能代替法律论证成立。最终报告项目绝对路径、核心文件和具体下一步。
