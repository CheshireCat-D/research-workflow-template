# 独立副本上的机械探针（另表，不计共同100分）

在A/C各组原成果封存后，用独立副本按各组实际提供的接口/脚本做探针。没有自动接口时记“未提供自动检查”，不直接当科研失败；允许基线自写等价机制。执行者不能看到未来探针标准答案，也不能由组织者替基线补写程序。

1. 悬空引用/无效后项批次：尝试一个含合法前项和非法后项的同一事务。检查是否拒绝，前项是否部分提交，原状态是否保留。对无批次接口的组记录人工协议/未提供机制，不虚构可执行事务。
2. 旧版本写入：取得逻辑记录v1，真实合法更新为v2，再用旧版本作写入请求。观察拒绝、冲突提示和v2是否保留。不能无意修改主链。
3. 漂移态checkpoint：B状态上保存新checkpoint/快照，仅比较快照的当前性和CALC/SYNTH的完成有效性。核心应仍报告活动stale；基线应按其自己的协议不把重拍指纹当复核。此项与C阶段内容判定对应，但这里记录机器接口自动保障。
4. `source_only`覆盖：没有local evidence/等价本地绑定的source locator不能被称为已经监测其内容。不要在本轮真改远端或新增假source-only变更。
5. 查询写入：对各组宣称只读的恢复入口，完整捕获前后bytes/mtime和目录mtime（不使用atime），检查是否创建锁、字节码或改材料。
6. 迁移执行：旧项目/旧toolkit不可达、公共缓存拒绝读，执行项目自己的入口。区分真正执行/只读取说明/资源不足。

另记自动返回的内容、实际调用、失败、为了实现等价功能新增的自写代码行/文件和维护步骤。将预制runtime体积与作者新增文件分开，不把一次exec内的多CLI操作算成一个动作。不用整文件字节推算token，也不用无控制的执行时间推算人类工时。
