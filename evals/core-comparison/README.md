# 理论审查精简与项目核心能力对照

**理论审查短路线实际少读约 69% 的指导文件字节；项目核心的明确优势是现成的记录引用校验和事务保护。六条正常研究链都完成了任务，恢复成功率没有显示组间差异。** 核心组在这些小项目上的外层工具调用更多，也仍需显式保存被覆盖研究文件的旧内容。

本轮只修改 RWT。个人技能包未改；九个技能名称和数量保持不变，新增一个按需理论审查参考。当前本地用户包为 80 个维护文件，另有一个包清单条目，SHA256 为 `1bf658b7895711bf786b3cf415a3c47dc2b214a31bace1d82e5b22ef00849ff2`。未发布到 GitHub。

## 理论审查入口

`rw-review` 先区分一次性审查和已有项目。给定命题／证明的单次审查进入 [短参考](../../skills/rw-review/references/theory-review.md)，不再默认加载项目协议、整个验证技能、文献技能和方法画像。已有 `project.json` 或明确持续登记／恢复的任务仍先恢复项目。新入口保留量词、概率过滤与可预测性、停时、交换极限的条件、严格反例、原文支持和有限检查的边界。

在两篇固定版本的 Howard 原始论文与同一构造草稿上，新旧入口各做一次全新上下文执行。两份报告分别匿名 AI 评审，均为 100/100；交付的有限检查脚本也在新副本重跑成功。这只支持本题未见质量损失，不是统计等效性证明或数学认证。

## 核心对照怎么做

两项真实材料项目，三组各一条四阶段链，共 **6 条研究链、24 个全新上下文**：

- **T：** 固定版本 [Howard 等论文](https://arxiv.org/abs/1810.08240v9) 的正态混合边界数值项目，作者工作参数 `rho=1→4`。
- **D：** [UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike%2Bsharing%2Bdataset) 的真实 2011 数据及原冻结模型，评价窗口从 10–12 月改为 11–12 月。模型、原始数据和计算器不变。

这些工作笔记、参数变更和角色由本次构造，不是来源作者的错误、真实远端更新或新的科学发现。科学计算被有意简化，以集中检验项目管理。

| 阶段 | 共同任务 |
|---|---|
| A 建档 | 保存同样的材料、约束、逻辑关系、版本与依赖；真实正常／无效试算；留存小型初始文件原字节及下一步 |
| B 漂移恢复 | 组织者只改工作参数文件；全新上下文只读识别直接和传递影响，保留独立来源分支 |
| C 修订 | 先保存漂移态断点并检查，随后实际复算、复核、保留旧内容、更新记录并保存最终下一步 |
| D 迁移恢复 | 项目移到新 Unicode 路径，旧项目和旧工具包路径消失；仅用项目实际留下的材料和工具只读恢复 |

三组分别为：强文件基线；读取 RWT 指导但不使用核心；读取相同指导并实际运行 RWT `init/register/checkpoint/resume`。前两组允许自写完整的指纹、版本、依赖、恢复和冲突保护程序，不是裸模型。核心组强制实际启用核心，因此这里不评价自动触发率。

共同义务、参数事件、成功路径和上游失败时的条件答案、部分分锚点、目标运行包与来源身份在首个生命周期执行者启动前冻结。57 个公开冻结文件的清单 SHA256 为 `bd6922d8655be77ff13941c6bc9ca0ccd578a3dd8e48543a092d173eb1c361f6`。不因不利结果重跑替换、补台账或改评分。详见 [协议](protocol.md)、[计划](study.json)、[冻结清单](freeze.json)、[评分](rubric.json)、[部分分规则](materials/shared/score-codebook.json) 和 [执行前独立审计](audits/key-audit.md)。

## 正常研究流程的结果

共同评分为 A20、B35、C30、D15。每链单独匿名初评；不同文件格式、接口名称、记录数量不加科研分。逐项结果见 [汇总](summary.json) 和 [匿名评审](adjudications/publication.json)。

| 组别 | T 理论项目 | D 数据项目 | T / D 外层工具调用 |
|---|---:|---:|---:|
| 强文件基线 | 100/100 | 100/100 | 34 / 29 |
| RWT 指导、自写文件流程 | 100/100 | 100/100 | 38 / 33 |
| 实际启用 RWT 核心 | 100/100 | 100/100 | 46 / 55 |

12 份 B/D 只读审计均确认文件字节、文件 mtime 和目录 mtime 不变。六次迁移均成功；各组从自己的持久材料恢复，没有由组织者补入标准交接。

独立审计在新副本运行 12 次原计算器，全部退出 0，数值 JSON 与 CSV 表均逐字节复现。另从原公式、CSV 和模型独立计算，未舍入数值最大绝对差为 `5.55e-17`；摘要按其显示精度一致。原来源、模型与代码身份均保持，初始和漂移态的小型四文件均有真实旧内容留存。D 的新窗口有 1460 小时／61 日，C0/C1 MAE 分别为 56.6412743099 和 41.2526225640，点降幅 27.1686%；它不表示模型经重训变好。

两种控制流程也能正确识别过期结果、维持历史和完成迁移。因而本轮没有证明核心提高了这些正常任务的正确率或恢复成功率。外层调用是自报观察，不等于等量工作、模型 token 或人类时间；也不能用两个小项目估计一般成本。完整负担记录见 [burden.json](burden.json)。

## 真正测到的工程差异

工程探针在封存项目的独立副本执行，不修改主链，也不加科研分。版本保护、关系引用校验和批次原子性分别测试，不能混成一个指标。

| 能力 | RWT 核心，两项目 | 自写更新器，两指导组 | 强文件基线 |
|---|---|---|---|
| 旧版本拒写 | 逻辑记录版本拒绝 | 状态／记录版本或 SHA 保护均成功 | T 有文件恢复 SHA 冲突保护；D 未提供写 API |
| 指向不存在记录的关系 | 拒绝，权威登记不变 | 原有目标字段被改为未知 ID 后仍接受并保存 | 未提供对应逻辑记录接口，不可比 |
| 错版本后项的批次 | 拒绝、整体回滚 | 拒绝、整体回滚 | 未提供批次接口，不可比 |
| 合法前项＋悬空引用后项 | 整批拒绝，前项不提交 | 前项与悬空关系一起提交 | 不可比 |
| 保存新断点后旧工作失效 | 自动检查仍保留 stale | 保留中间态重放后仍报告需复核 | 同样正确处理，部分依赖手工快照 |
| 只读和迁移入口 | 通过 | 通过 | 通过 |

关系探针修改的是各自实际存在的目标字段，而不是给控制组添加无关字段。未知 ID 确实不存在；每个批次的合法前项也在额外副本独立执行成功。原关系、候选、写后值、真实退出码和权威文件前后 SHA 均保留。见 [机械审计](audits/mechanical-audit.md)、[完整结果](audits/mechanical-audit.json)、[关系适配](audits/mechanical-audit/relation-adaptations.json) 与 [工程收据](audits/mechanical-audit/engineering.json)。

这支持一个具体优势：**使用核心可以直接获得统一记录模型下的引用一致性、版本检查和批次保护，无须每个项目重写这些通用约束。** 控制组成功实现的版本保护同样得到认可，不能称它们没有事务能力；其本轮更新器缺少关系引用校验，也不表示文件流程无法补上。

## 使用成本和能力边界

核心不会自动保存被覆盖研究文件的旧字节，登记历史和 SHA 不能恢复原文件。所有组都被同等要求先保留参数、结果、表和摘要；本轮的旧内容恢复依赖执行者真正留下这些文件。核心也不发现未登记依赖、未绑定文件或远端内容变化，不裁定科学真伪。

项目内预制运行资源为 68 文件、414,713 字节，另需构造记录、使用明确版本并显式复核受影响活动。本轮核心组的操作次数更多，未显示小项目省步骤。自写脚本的功能范围也不同，例如文件基线 D 还独立重算并校验数值，这是核心本身不提供的工作，不能把所有自写代码视为冗余开销。原有运行资源、自写入口、临时编排与科学验证脚本应分别看待。

对长期、多版本、多活动的项目，现成一致性保障具有明确用途；本轮没有量化其在更大规模、真实多人协作、并发竞争或长期维护中的收益。对一次性短审查，新增的轻入口更合适。没有把它与所有科研工具或 GitHub 项目作总体排名。

## 记录问题与解释范围

保留的执行偏差包括：一次读取／算摘要使用系统 Python 而非指定解释器；一次为清理停滞 PDF 检查而尝试进程清单，被沙箱拒绝；随包 `design/catalog.json` 访问的自报范围歧义；一个正常计算的首次 stdout 被重试覆盖，原验证失败与数值产物仍保留；少量旧字段或 CSV 一致性标记的记录矛盾。原报告和原始执行记录保留，没有以重跑替换。

本轮禁读的是未投放的评估设计和答案；原指令用 `design/` 简写，容易与合法工具包的稳定目录同名。P4 的 B 执行者据此自行设置读取防护，阻断了正式 `resume` 所需的随包目录，使该命令退出 2；随后通过手工盘点完成正确恢复。**该阶段不能计作一次成功的原生恢复命令演示**，也不据此判定核心程序有缺陷。其他原生命令和独立副本重放分别保留，不替换这次失败。原自报及组织者的范围解释都保留，未将读取随包目录写成读取了本轮答案。没有 OS 级访问审计，不能据自报或指纹证明所有访问均受系统隔离。

组织者曾凭目录过滤比例误猜一组用了 Git，已由原封存和独立审计纠正：该组实际使用自写文件管理脚本，本轮六组均未交付 Git 仓库。早期公开投影排除了 `.research`，最终已纳入其中可分发的研究元数据，并以 `recorded-research-state` 目录归档；原路径与文件摘要仍在清单中，源码发行不携带活动状态目录。私有盲评包始终完整，未发生据此扣分。三个组织者预检路径在公开审计 JSON 中改为逻辑定位符，原冻结清单和原始 SHA 不变，投影只允许该审计文件，不能用于题目／评分／科学参考。

每阶段原件先封存，六份初评使用全新上下文并不给组映射和外部执行历史。文件布局仍可能透露方法，不能称完美盲法。[第二轮内容复核](audits/content-consistency-review.md) 未见初评，独立建议六链仍各为 100/100；[逐阶段比对](audits/score-consistency.json) 保留报告 SHA 和记录差异。它与独立机械审计分别保留；执行和评分均为 AI，可能共享盲点，没有人类专家认证。

共同请求无模型或推理配置 override，实际生效模型、温度、随机种子与 token 限额不可得；不能声称已核验同模型同随机种子。24 个阶段是六条相依链，不是 24 项独立研究；两个特意选择的小项目仍有天花板效应。

## 复核入口

- 从仓库根运行 `python3 -B evals/core-comparison/validate.py`，检查冻结、文件身份、评分算术和记录闭合。`complete` 不自动表示科学正确或所有执行均成功。
- [输入身份](input-identities.json) 与 [公开投影](input-publication.json) 区分原私有字节和公开文本。原论文／CSV 不重分发；两份小 CSV 表公开时在冻结前统一为 LF，原 CRLF 摘要保留，计算器可重新生成原表。
- 各 `runs/P*/A..D/` 保留报告、原始执行记录的公开投影、可分发项目元数据和全文件摘要；完整私有项目含来源与运行副本，盲评没有应用公开大小裁剪。审计脚本反映实际暂存布局，需要映射逻辑定位符和提供已核验原始输入，不是新的产品命令。
- [完整性复核](audits/preservation.json) 确认个人包 516 个源文件／配置文件、前两轮对照 406 个文件及全部 24 份封存均未改变；七份核心登记／检查点／恢复逻辑文件也保持本轮开始时的字节。
- [本轮软件回归](audits/software-check.json) 实际执行 412 项，399 项通过，13 项原生 Windows 测试在 macOS 跳过，七组检查通过。[用户包核验](audits/user-package-check.json) 含两次构建字节相同、清洁运行和迁移测试；软件与发行检查另见 [当前验收记录](../current/latest.json)。本轮成果仍属本地未发布改动。
