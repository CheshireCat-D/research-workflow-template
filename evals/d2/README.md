# 基础任务回归素材

本目录保存当前回归测试使用的三项离线合成任务、独立执行者的实际产物和规范化后的最终登记数据。执行者分别从原始任务与材料开始，使用项目内接入的技能完成问题细化、材料核对、实际工作、短稿、审阅和恢复记录；未获得评分笔记、预期答案或其他执行者结果。任务不是由关键词匹配测试替代。

| 任务 | 原始材料 | 实际短稿 | 实际工作 |
|---|---|---|---|
| 数学证明 | [任务与输入](cases/proof/task.md) | [讨论稿](recordings/proof/outputs/manuscript/report.md) | 单点反例、几乎处处版本证明、代表元语义、连续性修复和有限采样的限制 |
| 计算实验 | [任务与输入](cases/computation/task.md) | [实验短稿](recordings/computation/outputs/manuscript/report.md) | 36 组等求值预算比较、18 个独立基准、实际代码与逐项结果 |
| 史料解释 | [任务与输入](cases/history/task.md) | [解释短稿](recordings/history/outputs/manuscript/report.md) | 七份节录的来源审计、时间线、材料派生关系与竞争解释 |

这些是小型研究行为测试，不是真实新发现、完整学科复现或专家认证。数学推导未使用证明器；计算限于六个函数和三档预算的双精度实现；史料完全虚构且只提供节录。稿件的起草与审阅得到实际测试，翻译、压缩、期刊格式和外部文献数据库尚未单独行为测试。

## 记录如何组织

每项 `recordings/CASE/` 包含：

- `outputs/`：执行者实际交付的推导、代码、结果、短稿与审阅；保留原始科学内容。
- `recording.json`：最终记录数据、明确登记顺序、下一步、输入和产物指纹。原始案例输入通过 `case_files` 引用，不重复保存；自动回归将它们复制进新临时项目。
- `execution-summary.json`：执行者的运行摘要，保留曾发生的错误和恢复说明；其中的日志路径为原始隔离运行中的索引，不是本目录内的文件。
- `observed-check.json`、`observed-resume.json`：完成后另行实际读取原项目得到的接口检查输出。

规范化快照用于重放最终状态；重放会创建新的项目身份、版本为 1 的记录和新检查点，不重建原过程的全部登记历史。命令原始日志和安装运行时不重复分发。唯一有路径替换的产物会在 `output_normalizations` 中列明原指纹与转换：只将开发机器的执行路径换为 `PROJECT`／`RUN`／`TOOLKIT`／`PYTHON` 占位符，不改数值或科学论证。

`d2` 是保留的素材组标识，不是软件版本；目录中没有另一套旧软件。执行时三项目使用同一份当时接入的技能资源。任务中发现自由填写 CLI 学科／方法 ID 容易出错，随后在共用接入协议补入稳定目录链接与示例。原安装副本完整，源版本比较因这项修订提示不同；没有静默覆盖旧副本。原失败与提示保留在运行摘要中。当前版本连接与重放由自动测试另行执行，不能把它描述为重新执行了三次独立模型任务。

## 可以重复检查什么

从仓库根运行 `python3 tools/check_core.py`，会执行接口、技能接入和 `tests/test_task_replays.py` 的五项回归。它们以当前运行时重建三个临时项目，登记实际记录，检查只读恢复和材料变化提示，重跑数学样例的有限输入检查，并重新执行计算脚本，将全部结果与独立计算及闭式诊断核对。数学脚本的检查范围是文件、有限算术与篇幅，不是自动验证证明。测试不会写回本目录，也不会调用模型。

计算样例可单独复跑，但需先按 `recording.json` 将输入复制到新项目的指定位置。使用新的输出目录：

```text
python3 -B PROJECT/artifacts/run.py --output-dir NEW-OUTPUT
```

数学证明和史料解释的内容需要另行阅读材料与产物复核，不能靠比对措辞或登记通过自动判定。[独立内容审阅](independent-review.json)保留这些材料实际检查的范围与限制；软件的最新执行结果只看[当前核验记录](../current/latest.json)，架构场景的任务对应见[覆盖记录](../d3/coverage.json)。
