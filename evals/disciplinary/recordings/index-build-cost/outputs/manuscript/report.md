# 重复键查询的端到端成本

对8条有序记录，我们实现了逐次完整扫描的路线L和先建索引的路线I。两者均返回重复键最后一条记录的值，未命中返回null。a、b应分别返回70、50，不能任取旧值；给定10次查询的返回值逐项一致。

按合同，L每查询比较8次；I先写入8条记录，再每查询查找1次。各负载独立构建索引，结果如下：

| 查询次数 | L总成本 | I构建+查询 | L总/I总 |
|---:|---:|---:|---:|
|1|8|8+1=9|0.889|
|2|16|8+2=10|1.600|
|10|80|8+10=18|4.444|

I在单次负载中成本较高，在两次及十次查询中成本较低。一般有C_L=8m、C_I=8+m，I较低的条件为m>8/7；有限m下总成本比始终小于8。

重复键使索引覆盖旧值，虽最终仅5个键，构建仍计8次写入。重复查询各计一次调用，较大负载摊薄构建成本；本实现没有答案缓存。两次未命中仍分别需要完整扫描或一次查找。

这些数值是键比较、写入和查找的抽象操作计数，不是墙钟时间或真实机器加速倍数。原稿忽略构建成本和最后值语义，因此不能据此声称所有负载“至少快八倍”。
