# 封闭规范文本边界修复记录

独立复核指出原脚本的范围声明强于实现：它只检查第5、7、9条中的若干片段，若保留片段并追加条件，仍沿用旧模型。本次先从未修改的脚本重现该缺陷：在第5条中英文本末尾同时追加监督申请人仍须完成培训，旧程序退出0、仍将甲判为可申请。该变体下旧模型已经过时，不能把退出0当作正确。原脚本、原结果、原执行清单和错误变体输出全部保留在checks/repair-v1/before/。

修复保持本案例的封闭范围，不推断任意法律文本。artifacts/run.py现在先核对完整规范块：标题、材料身份与共同权威/时点说明、D0第1条、第2、5、7、9条及已有英文版本，须与本次人工审阅的原有规范逐行完整一致。仅忽略空行和每行首尾空白；额外文字、删改、重排、新增条款以及申请人事实后的额外内容均拒绝，要求重新法律审阅。这个边界刻意严格，未把某些改写宣称为逻辑等价。未支持的输入退出2，明确报告Unsupported normative text或Unsupported content，不创建结果目录。

申请人事实不固化为原三人的答案。程序继续从指定输入按记录的年龄、居住、培训、获准监督、禁止令语法重新提取并计算，阈值来自获支持的第2条；本次将甲年龄改为17、乙改为19、丙改为无禁止令，实际结果依次为否、是、是。申请人之外的未知叙述不能被悄悄忽略。

实际核验：中英同时追加监督须培训、仅英文追加、另增第10条、将“或”改为“且”四种规范变体均退出2，无结果目录；原输入两次正常运行均退出0，结果哈希相同，原甲/乙/丙结论仍为是/否/否。checks/repair-v1/repair-results.json保留逐项状态和输入哈希，checks/repair-*.stdout及.stderr保留原始执行输出。修改脚本后登记更新前的check退出1，真实报告过期指纹；该中间失败也保留，未直接抹除。

冻结inputs及原有法律正文notes/analysis.md、manuscript/draft.md、manuscript/report.md的哈希未变。CLI显式更新脚本、结果、证据与依赖活动，并保留版本历史。下一步由独立复核者重放主反例与一个未列出的附加规范条件，确认新程序拒绝且不创建输出；若未来有意支持另一规范版本，应先重新做条文分析，再明确修改封闭支持契约及回归证据。
