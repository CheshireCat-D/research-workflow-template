# 参考迁移、去个人化与开源边界

本模板独立实现通用核心和研究指导，没有调用个人包的导出器，也没有复制其技能源码。个人包的架构与维护经验是参考；新增学科和能力需有相应实现与实际任务证据，不能只靠扩写README。

## 参考矩阵

| 个人包中的能力 | 新项目的处理方向 | 应保留的关键能力 |
|---|---|---|
| 工作流、检查点、执行记录与项目模板 | 重写公共接口；后续逐文件评估可复用实现 | 恢复状态、真实失败记录、依赖变更与只读检查 |
| 严格数学、物理核验 | 方法参考，保持专门义务 | 假设与证明、量纲、守恒、极限、误差及适用范围 |
| 兴趣澄清、选题构建与候选对抗 | 重写为 question、innovation、candidates 的互补职责 | 已定选择、证据对照、实际障碍与最小检查 |
| 阅读、引用与定理层文献比较 | 重写通用来源层；定理比较仅属相应方法 | 身份核对与内容支持分开、精确来源锚点 |
| 起草、润色、翻译与压缩 | 中性写作协议，模式按需加载 | 保真、作者声音、论证力度与语言约定 |
| 图表、格式、审稿与返修 | 原创部分逐项审核，外部后端可选 | 数据忠实、图表语义、渲染核对、真实修改证据 |
| 第三方技能及其内化资源 | 先登记外部来源，暂不复制 | 待逐文件来源与许可核查后决定 |
| 元数据、隐藏字符与来源审计 | 可选附件，非默认研究阶段 | 区分实际可查范围，不保证“无 AI 痕迹” |
| 本机环境、全局入口、历史 QA、真实稿件与截图数据 | 不迁移 | 只借鉴维护思路，不复制材料 |

已有来源记录只是调查线索。标记为本地编写、存在某个 LICENSE 或记录仓库 commit，均不能代替对最终引入文件的完整审查。内化的期刊润色资源、其他第三方片段和图像素材要分别处理；对尚无明确许可依据的内容，不直接打包发行。

## 去个人化规则

- 删除个人贡献标尺、奖项愿景、默认期刊等级、学习阶段、语言习惯和特定列的排版偏好。通用版保留用户可配置的目标、作者风格和文类设置。
- 新写中性问题、配置和合成材料。不得把实际论文表格、私人导师信息或个人工作记录改名后用作公共示例。
- 技术 ID 与包名中性化，避免品牌名造成期刊背书或默认目标的印象。
- 不携带绝对机器路径、用户名、缓存、凭据、运行环境、私密状态和指向个人包的符号链接。
- 公开日志不包含私密文件路径或身份映射。数据无法公开时提供可说明原因的受控访问或合成示例，不以开源为由强制公开。

## 路径与安装设计

仓库资源相对仓库根解析；项目资源相对显式项目根解析。移动目录、中文路径和空格路径应进入测试。受控数据用安全 ID 加本地未跟踪映射配置；包内资源不允许通过符号链接逃逸。

个人包与通用版没有自动同步、跨包运行依赖或共用状态；适合的改进经逐项审阅后各自实现。项目内技能接入使用 `rw-` 前缀，并显式选择安装范围；默认不覆盖已有全局入口。导入个人项目要另行指定源与新输出位置，先预览映射，不原地迁移。

核心元数据工具仅使用 Python 标准库，科学工具按需检测与锁定；最低解释器与实际平台范围见[当前核验记录](../evals/current/latest.json)。不要把当前机器的版本写成所有用户必须安装的版本。

## 文件来源与发行

当前原创代码、指导与合成例采用根目录MIT许可证。维护源的逐文件声明与SHA-256在 `provenance/file-origins.json`，规则见 [来源说明](../provenance/ORIGIN.md)。外部方法资料仅引用，不复制全文；[方法来源记录](../profiles/sources.json) 保留版本、访问范围与限制，CI所用外部动作也有固定版本来源。未来若引入第三方代码，需另记来源URL/ref、原始许可和通知；不能沿用原创声明。

来源清单生成只记录经复核的声明与字节，不独立证明版权、研究质量或许可适用性。本模板的许可证不替个人整包或所链接的外部文献重新授权；公开清单不包含个人内部路径。

## 发布边界

本地设计、可运行原型、候选发布与远程发布是不同里程碑。发布前需完成：可安装入口与依赖检查、代表性任务验证、去个人化与敏感信息检查、来源与通知核对、干净环境安装测试、清楚的能力及限制说明。具体要求与证据见 [发布验收](10-release-readiness.md)；打包工具只从明确的公共维护目录构建，检查私有状态、链接、常见凭据模式和机器路径，再生成可校验归档。

GitHub 仓库、远程推送、公开发布、第三方服务连接和实际数据上传不由本设计自动触发。后续在用户明确要求相应动作时进行。模板自身不承诺接收率、自动发现、自动伦理批准或无人负责的科研闭环。
