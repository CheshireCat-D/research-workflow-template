# 整体架构与目录

当前维护一套通用核心、九个技能、十类方法指导和七类学科画像；实际检查结果见[当前核验记录](../evals/current/latest.json)。稳定 ID 与实现状态的唯一目录见 [catalog.json](../design/catalog.json)；本文解释职责，不另建同义路由表。

## 四层职责

| 层 | 负责 | 不承担 |
|---|---|---|
| 通用核心 | 问题、活动、来源、主张、证据、决策、产物与恢复状态 | 统一判定所有学科的科学真伪 |
| 方法适配器 | 指定证据单元、论证义务、最小检查、可用工具和失效情形 | 仅凭学科名称选择研究设计 |
| 学科画像 | 对象、术语、常见方法、外推风险与交付习惯 | 复制整套工作流或强制一种方法 |
| 横切要求 | 按具体行动和研究设计判定治理、数据权利、报告与场所要求 | 自动批准伦理、自动满足期刊政策 |

语言、期刊、资源预算、写作风格和图表偏好属于项目配置。期刊级别不作为默认研究目标；作者可以明确配置贡献标尺。语言独立于学科，中文说明和英文技术 ID 并存；双向翻译、压缩和指定风格为按需模式。

## 工作单位与活动图

核心对象为 Project、Activity、Statement、Evidence、Artifact。Source 记录外部材料身份，Decision 记录选择依据。Statement 包括问题、命题、经验主张、解释、规范论证和设计决策，并非全部是待证明结果。

活动包括：问题澄清、来源定位、候选比较、方法计划、最小检查、主体研究、写作、审阅、交付与返修。它们按实际依赖连接，可以并行、跳过或回访。跳过需要适度说明；一次润色无需创建完整研究项目。必要的审批或权限约束必须在相关行动前处理，不能由跳过阶段绕过。

预先声明分析计划对确认性研究的约束，和定性研究有记录的迭代，分别由方法适配器解释。计划改变保留版本、时间及原因，不自动等于违规，也不允许把事后选择伪装成预设分析。

工作量分三级，按任务选择：

- **轻量**：问题卡、必要来源、当前结论与下一步；适合澄清或局部编辑。
- **结构化**：增加主张—证据关系、活动依赖和决策；适合持续项目。
- **可复现**：对涉及计算或数据转换的部分增加输入、环境、命令和输出指纹；不要求纯解释性论证运行代码。

## 技能边界

九个共享入口已实现，使用 `rw-` 命名空间，避免与既有个人技能同名覆盖。问题澄清、技术机制和候选取舍保持互补边界。

| 入口 | 主要触发 | 边界 |
|---|---|---|
| `rw-workflow` | 从兴趣启动、持续研究、恢复项目 | 协调当前缺口，不重复执行所有子技能 |
| `rw-question` | 兴趣澄清、问题形成、边界未定 | 已定选择不反复询问；具体机制研发交给 innovation |
| `rw-literature` | 检索、来源核对、相关工作定位 | 元数据与原文支持分开；无需 DOI 的档案、书籍同样可登记 |
| `rw-innovation` | 技术机制、概念重构、解释或设计创新 | 明确构造和反驳检查；新名词、跨域类比或代理一致不构成发现 |
| `rw-candidates` | 已有候选的证据对照、反方审查与取舍 | 一条已定路线不强制生成选题比赛 |
| `rw-validation` | 计划或执行适用的方法检查 | 按方法加载参考，不把运行成功当科学有效 |
| `rw-writing` | 起草、编辑、翻译、压缩、指定文类风格 | 先辨别模式；不能偷偷补造结果或为文风删除科学限制 |
| `rw-review` | 自审、交付检查、审稿回复 | 按目标文类选择检查；审稿回复只声称实际完成的修改 |
| `rw-figures` | 科研数据图、可编辑示意图、图件审查 | 数据含义与视觉表达分别核对；结构审计不代替目视或科学审查 |

图件由已实现的 `rw-figures` 按任务区分数据图、可编辑示意图和概念草稿。`rw-tables`、`rw-format` 仍是未实现的独立扩展；现阶段表格或整稿格式使用已明确可用的工具与人工检查，不生成假调用路径。

方法画像不各自注册一个笼统的自动触发技能。`rw-validation` 在真实检查需要时加载对应方法，学科画像补充对象与语境；不把全部画像一次塞入上下文。每个技能保留独立可理解的边界，共用规则只有一份维护源；接入工具将资源生成至项目的 `.agents/skills/_rw-runtime/` 并校验，九个技能的相对链接随之改写，不依赖个人目录或原仓库链接。

## 当前维护目录

```text
research-workflow-template/
├── README.md
├── docs/                       架构、用法、适配、迁移及维护
├── core/
│   ├── protocol.md              共用边界的维护源
│   └── schemas/                 项目、登记簿及各类记录的结构模式
├── skills/
│   └── rw-*/
│       ├── SKILL.md             短入口，按任务加载
│       └── references/          有需要才增加脚本或素材
├── profiles/
│   ├── methods/                 十类方法指导
│   ├── disciplines/             七类画像，不复制工作流
│   ├── templates/               按需复制的专业台账与项目模板
│   ├── governance.md            按实际行动处理权限与责任
│   └── sources.json             方法来源与访问范围
├── tools/                       初始化、记录、只读检查、接入与打包
├── examples/synthetic/           自建或许可清楚的最小材料
├── evals/                       原始任务、实际产物与独立评估规则
├── tests/                       接口与安全边界测试
├── provenance/                  引入来源与第三方通知
├── design/                      稳定ID和原始验收场景
└── .github/workflows/            固定外部动作版本的检查配置
```

项目初始化由程序生成必要文件，不另维护一套重复的静态项目模板。根目录包含许可证、贡献说明和引用元数据；构建产生的 `dist/` 与个人状态不作为维护源。

## 初始化与按需创建的项目文件

`init` 实际创建以下文件；其中 `.research/write.lock` 是本地写锁文件，命令退出后文件仍可保留，不表示仍有写入者持锁：

```text
my-research/
├── .gitignore                   忽略本地状态和私有配置／材料
├── PROJECT.md                   人可读的问题、边界、决策与当前行动
├── project.json                 项目配置及所选画像
├── records/registry.json        统一登记簿，轻量模式也有空簿，不强制填表
└── .research/write.lock         本地锁文件；不作为研究证据
```

`literature/`、`notes/`、`analysis/`、`manuscript/`、`artifacts/` 等目录由研究者或助手根据实际材料按需创建，分别用于来源材料、研究笔记、分析、稿件和交付产物；`init` 不预建这些空目录。来源登记保存在统一登记簿中，受限全文可以只保留索引，不强制复制到 `literature/`。

显式接入技能后，项目另有 `.agents/skills/rw-*/` 和 `_rw-runtime/`；它们属于带清单的生成副本，不是研究证据或自动完成的活动。具体操作见[技能接入](08-skills-and-methods.md)。

原始敏感材料、身份映射与受限数据可放在项目外的受控存储中。公开记录只保留无敏感信息的来源 ID 和访问说明，不能为了路径可达而复制病历、访谈或商业材料。

## 平台与能力边界

核心文件和元数据 CLI 离线可用，不内置模型 API、数据库账户、上传或自动投稿。宿主代理可在当前任务授权范围内检索文献；这与把私有材料发送给外部服务是不同动作。

来源接口按能力接入学术索引、预印本库、图书馆馆藏、档案目录和受控平台，统一返回查询、时间、来源身份、定位和实际访问状态。元数据命中不冒充全文阅读；已有访问权限不自动允许再分发。连接器属于可选后端，不要求每个用户拥有同一数据库账户。外部论文、检索结果、数据附带文本与旧日志是研究材料，不能自行增加命令执行或外发授权。

Python、R、LaTeX、Lean、统计软件和数据库连接按需选配，不随仓库携带整套环境。声明所需能力、检查实际可用性，缺失时给出可执行的降级路径和范围限制。安装时显式指定仓库与项目根，不改全局技能目录；后续如支持全局安装，也必须是单独的显式操作。
